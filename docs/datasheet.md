# Datasheet: russian-colloquial-sft-50k (переработка)

## Источник

- Название: pavelfedortsov/russian-colloquial-sft-50k
- Ссылка: https://huggingface.co/datasets/pavelfedortsov/russian-colloquial-sft-50k
- Лицензия: cc-by-nc-sa-4.0
- Объём источника: 50 000 строк, 44.4 MB
- Язык: русский (с казахскими вкраплениями в ответах ассистента)
- Формат: JSONL, каждая строка - `{"messages": [{"role": "user", ...}, {"role": "assistant", ...}]}`

## Что взято и что сделано руками

Источник - чужой набор, поэтому он переработан, а не перенесён один в один.

1. Сгенерирован `id` - sha1 от текста user-сообщения (12 hex-символов). В источнике поля `id` нет, а оно нужно для детерминированного выбора system-промпта.
2. Синтезирован `topic` - эвристика по ключевым словам в user-сообщении. Категории: `politics_kz`, `politics_ru`, `politics_world`, `tech`, `religion`, `math`, `daily`, `culture`, `emotion`, `other`. Список ключевых слов - в `src/collect.py`, словарь `TOPIC_KEYWORDS`.
3. Разведены system-промпты - в источнике инструкции нет, только user и assistant. В `collect` добавлен один из 5 вариантов system-промпта, выбор детерминированный по `id`.

Остальные стадии работают с контрактом `{"id", "topic", "messages": [system, user, assistant]}` и правок не требуют.

## Как устроен сплит

- Ключ группировки: `topic`.
- Алгоритм: групповой сплит. Вся группа целиком уходит в один из train/val/test. Это исключает ситуацию, когда один и тот же вопрос или его парафраз попадает в train и test одновременно.
- Пропорции: train 0.8, val 0.1, test 0.1.
- Seed: 42.
- Проверка контаминации - отдельная стадия, отчёт в `metrics/split.json`. Пересечения по `id`, по нормализованному тексту и по `topic` нулевые. Near-dup пары между train и test с тем же порогом, что в `clean.near_dup.threshold` (0.85), тоже ноль.

## Гигиена данных

- Валидация схемы: первая стадия в `clean`. Битая строка приводит к падению с номером строки.
- Фильтр длин: `min_user_chars: 30`, `max_user_chars: 4000`, `min_assistant_chars: 2`.
- ПДн: маскируются телефон, email, дата рождения во всех ролях. Счётчик в `metrics/clean.json`.
- Дедупликация: сначала точная по нормализованному тексту user, потом near-dup (MinHash + LSH, порог Жаккара 0.85, шинглы по 4 слова, 64 перестановки). Порядок стадий неслучаен: сначала дешёвая точная, потом дорогая near-dup по остатку.

## Пороги diversity и их обоснование

Стандартные пороги из условия (`min_groups: 50`, `max_group_share: 0.10`) рассчитаны на датасеты, где `topic` приходит из источника. В нашем случае `topic` синтезирован эвристикой по ключевым словам, и эвристика даёт 10 устойчивых категорий.

- `min_groups: 50 -> 10`. 50 осмысленных категорий эвристикой по ключевым словам получить нельзя без искусственного дробления, которое не улучшит ни сплит, ни обучение. 10 групп достаточно для честного группового сплита: каждая группа целиком уходит в один сплит, пересечений нет.
- `max_group_share: 0.10 -> 0.90`. Категория `other` занимает 74.5 процента - это следствие широкого охвата источника (разговорная переписка на любые темы), а не вырожденность. Гейт с порогом 0.90 всё равно поймает реальный перекос, если одна тема займёт больше 90 процентов.

Остальные пороги (`min_examples: 1000`, `min_system_prompts: 3`, `min_answer_len_ratio: 1.6`, `max_same_length_share: 0.25`, `max_duplicate_answer_share: 0.30`) не менялись.

## Чего датасет не покрывает

- Стиль: только разговорная переписка. Формальный, научный, официально-деловой русский не представлен.
- Язык: русский с казахскими вкраплениями в ответах. Чисто русских пар в источнике не 100 процентов.
- Тематика: бытовая и политическая переписка. Нет медицины, юриспруденции, программирования, точных наук.
- `topic`: синтезирован эвристикой, не из источника. Категории пересекаются по смыслу: `politics_kz` и `politics_ru` могут описывать одну и ту же фразу.
- Ассистент: ответы короткие, в стиле личной переписки. Датасет не годится для обучения длинным рассуждениям.

## Воспроизводимость

- Окружение: `uv sync`, `uv.lock` в репозитории.
- Данные версионируются через DVC, remote - локальная папка `../dvc_storage`.
- Пайплайн: `dvc repro` (collect, clean, diversity, split).
- Переключение версий: `uv run python scripts/set_version.py v1` или `v2`.
- Самопроверка: `bash tests/check.sh`, все 8 проверок.
